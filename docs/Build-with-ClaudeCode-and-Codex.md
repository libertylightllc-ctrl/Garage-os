# Building GarageOS with Claude Code & Codex — Execution Guide

A practical, copy-paste guide to turning the spec into a working Phase 1 MVP using AI coding agents. Written for someone who is product-strong and may be light on code.

---

## 0. Mental Model: What These Tools Are

- **Claude Code** — Anthropic's agentic coding tool that runs in your **terminal** (and desktop/mobile app). It reads your whole repo, writes and edits files across the project, runs commands, and can use MCP servers. Best for navigating a large codebase and making multi-file changes.
- **Codex** — OpenAI's coding agent (CLI + IDE extension + cloud). Same idea, different vendor. You do **not** need both; pick one as primary. Using two just means two subscriptions and two styles in one repo.

**Recommendation:** Use **one** as your primary builder. If you have a Claude Pro/Max subscription, make Claude Code primary and (optionally) use Codex as a second opinion on tricky bugs. The workflow below works identically with either — only the install command and auth differ.

---

## 1. Prerequisites (one-time, ~15 min)

You need a terminal. On Windows, install **WSL** (Ubuntu) and do everything inside it.

```bash
# 1. Check Node (needed for the npm install method)
node --version   # must be v18 or higher; v22 LTS recommended
# If missing, install the LTS from nodejs.org, then close & reopen the terminal.

# 2. Check git
git --version    # any recent version is fine

# 3. (optional but recommended) a GitHub account + the gh CLI for backups
```

> RAM: 8GB+ recommended. No GPU needed — all AI runs on the vendor's servers. You need a paid plan: Claude Pro/Max (or API billing) for Claude Code; a ChatGPT Plus/Pro or API plan for Codex.

---

## 2. Install Your Agent

### Option A — Claude Code (recommended primary)
```bash
# Native installer is the recommended method (no Node needed for the binary itself):
#   see code.claude.com/docs/en/setup for the current install command per OS.
# OR the npm method (requires Node 18+):
npm install -g @anthropic-ai/claude-code

# First run inside a project folder triggers browser OAuth login:
cd ~/projects
claude
# Follow the browser prompt. A session token is stored locally.
# Do NOT use sudo with npm -g. If you hit EACCES errors, configure a
# user-writable npm dir (~/.npm-global) and add it to PATH — never sudo.
```
To update later: `npm install -g @anthropic-ai/claude-code@latest`.

### Option B — Codex
Install the Codex CLI per OpenAI's current instructions and authenticate with your OpenAI account/API key. Then run it from inside your project folder the same way.

## 3. Create the Project & the Agent's "Constitution"

The single biggest quality lever with AI agents is giving them a **persistent instructions file**. Claude Code reads `CLAUDE.md`; Codex reads `AGENTS.md`. Create both with the same content so the project is portable.

```bash
mkdir -p ~/projects/garageos && cd ~/projects/garageos
git init
```

Create `CLAUDE.md` (and copy it to `AGENTS.md`) with this:

```markdown
# GarageOS — Agent Instructions

## What we're building
Phase 1 MVP of GarageOS: a GCC garage operating system. UAE only.
WhatsApp-first. AI proposes, humans confirm. Read GarageOS-Technical-Spec.md
and GarageOS-GCC-Master.md before making decisions.

## Stack (do not deviate without asking)
Next.js + TypeScript + Tailwind + shadcn/ui, Node API routes, PostgreSQL,
Prisma, Auth.js/Clerk, Anthropic API for AI, WhatsApp Business Cloud API.

## Rules
- Work in SMALL steps. After each step: it must run, be committed, have a test.
- Never invent a different library when the spec names one.
- All money is Decimal, NEVER Float (accounting integrity).
- Staff (4 roles) are auth Users; Customers are a separate passwordless,
  phone-keyed model (WhatsApp-first — customers never install an app / log in).
- AI intake is propose-confirm: it writes a Booking row, never auto-creates a
  JobCard. A human advisor confirms.
- Every AI call must write an AiEvent row (incl. model) for usage metering.
- Invoice model keeps clearanceStatus + qrPayload from day one (KSA hook);
  invoice lines are a snapshot; numbering is gapless & per-garage.
- Accounting is zero-entry: ledger rows are generated by services, never by hand.
- Copilot is read-only and ALWAYS scoped to the owner's garageId — no raw SQL.
- Ask me before: installing a new dependency, changing the schema, or
  touching auth/payments.
- Keep screens to max 3 primary actions. Mobile-first. i18n/RTL infrastructure
  is wired in Step 1 (Arabic + English); translations land progressively.

## Definition of Done is in GarageOS-Technical-Spec.md §4. Build in the order in §5.
```

Now drop the two `.md` files from this project (Master + Technical Spec) into the repo root so the agent can read them.

```bash
git add . && git commit -m "Project constitution + specs"
```

## 4. The Core Workflow (repeat for every feature)

This is the loop. It's the whole job.

1. **Plan first, code second.** Start each session by asking for a plan, not code:
   > "Read CLAUDE.md and GarageOS-Technical-Spec.md. We're on build step 1 (scaffold + Prisma schema). Give me a step-by-step plan and the exact files you'll create. Don't write code yet."

2. **Approve / correct the plan.** This is where your product judgment pays off. Fix wrong assumptions now — it's free.

3. **Let it build one step.**
   > "Good. Implement step 1. Stop when the app runs and the schema migrates. Then show me how to verify it."

4. **Verify it runs.** Actually run the command it gives you (`npm run dev`, open localhost). If it breaks, paste the **exact error** back. Agents fix their own errors well when given the real message.

5. **Commit.**
   > "Commit this with a clear message."
   (or run `git commit` yourself.)

6. **Next step.** Move to build step 2. Keep sessions focused on one step.

> **Golden rules:** small steps; always have a running app; commit after every green step; paste real errors; make it write tests. Never let it do 5 features in one go — you lose the ability to tell what broke.

---

## 5. Concrete First Three Prompts (copy-paste)

**Prompt 1 — scaffold**
> Read CLAUDE.md and the two spec files. Scaffold a Next.js + TypeScript + Tailwind + shadcn/ui app with Prisma and PostgreSQL. Create the Prisma schema exactly per Technical-Spec §2. Set up a local Postgres connection via .env (show me what to put there). Run the first migration. Stop when `npm run dev` serves a blank page and the DB has the tables. Show me how to verify.

**Prompt 2 — auth + role routing**
> Implement build step 2: Auth with 4 STAFF roles (OWNER, ADVISOR, TECH, ACCOUNTANT). Customers are NOT auth users — they're a separate passwordless, phone-keyed model handled later (WhatsApp-first). After login, each staff role lands on its own near-empty home screen with the right title. Add a seed script that creates one test user per staff role plus a couple of sample Customers. Tests for the role-routing logic. Stop when I can log in as each staff role and land on the right screen.

**Prompt 3 — the spine (job card + advisor timeline)**
> Implement build step 3: the JobCard model is already in the schema. Build the Service Advisor timeline UI: ARRIVED → INSPECTION → ESTIMATE → APPROVED → REPAIR → INVOICED → DELIVERED, advancing one tap at a time, max 3 actions on screen. Persist status changes. Test the state transitions. Stop when I can create a job card and tap it through every stage.

## 6. Wiring the External Services (when you reach those steps)

- **Anthropic API (AI features):** get an API key from the Anthropic Console, put it in `.env` as `ANTHROPIC_API_KEY`. Tell the agent to use it in IntakeService/CopilotService/ExpenseOcrService and to write an `AiEvent` per call.
- **WhatsApp Business Cloud API:** requires a Meta Business account + a verified number + webhook URL. Tell the agent to build the webhook receiver and outbound template sender; you supply the tokens in `.env`. (This has a Meta-side approval step — start it early.)
- **Payments:** pick a UAE PSP or Stripe; never hardcode keys — always `.env`.

> Security: secrets live in `.env` (git-ignored), never in code, never pasted into chat history you share. Ask the agent to add `.env` to `.gitignore` in step 1.

---

## 7. Using Claude Code and Codex Together (optional)

Because both read a plain-text instructions file and a normal git repo, you can switch freely:
- Build primarily with one agent.
- When stuck on a gnarly bug, open the other in the same folder and ask it to review: *"Here's the failing test and error. Diagnose without rewriting unrelated code."*
- Commit between hand-offs so each agent sees a clean state.
- Keep `CLAUDE.md` and `AGENTS.md` in sync (same content) so neither drifts from the plan.

---

## 8. Guardrails So You Don't Get a Mess

1. **One step per session.** The fastest way to an unmaintainable pile is "build the whole app." Don't.
2. **You run the app, not just the agent.** If you never see it work, you don't know if it works.
3. **Commit constantly.** Every green step. This is your undo button.
4. **Protect schema, auth, payments.** Make the agent ask before touching these (it's in CLAUDE.md).
5. **Watch AI cost early.** The `AiEvent` meter exists for a reason — Layer-2 usage can outrun the subscription.
6. **Ship the Definition of Done, nothing more.** Phase 1 is UAE-only. Resist KSA/marketplace/fleet until the wedge is proven with real garages.

---

## 9. What "Done with Phase 1" Looks Like

You can log in as all four staff roles (customers are passwordless, via WhatsApp); a customer books by voice/photo and an advisor confirms; the advisor taps a job from arrival to delivery; an estimate goes out on WhatsApp and comes back approved; an invoice with UAE VAT generates and auto-writes ledger entries; AR shows 🟢🟡🔴; the owner sees five metrics and asks the copilot three kinds of question; every AI call is metered; the UI works in Arabic and English. Then you put it in front of 5–10 pilot garages and measure the four hypotheses.

That's the whole Phase 1. Build it small, prove the wedge, then expand.
